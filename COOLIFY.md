# Coolify Deploy

Nortys is standardized for a quick Coolify deploy with one application container and one PostgreSQL service.

## Recommended Setup

Use the root `compose.yml` in Coolify. It does not require a committed `.env` file; configure variables in Coolify or provide them through a local `.env` when testing with Docker Compose.

The `nortys` service builds from the root `Dockerfile`, serves the web app on port `5173`, proxies `/api/*` to the bundled API, and stores uploads on a persistent filesystem volume.

## Auto Redeploy From Git

For the easiest flow, create the resource from your Git repository using the Docker Compose build pack:

```txt
Build Pack: Docker Compose
Base Directory: /
Docker Compose Location: /compose.yml
Branch: main
Port: 5173
Healthcheck path: /api/health
```

Then enable automatic deploys:

1. Open the Nortys resource in Coolify.
2. Go to `Advanced`.
3. Enable `Auto Deploy`.
4. If you connected through the GitHub App, Coolify can redeploy automatically on pushes to the selected branch.
5. If you used a deploy key or public repository, configure the webhook URL and secret shown by Coolify in GitHub under `Settings > Webhooks`.

Use only the `push` event for the webhook.

## Production Build

The production image installs only dependencies required to compile the API,
web app, email templates, and permissions package. Test and local development
tools are skipped.

The Docker build uses the pnpm store cache and copies packages into the build
layer instead of creating a large link tree inside Docker overlay storage. The
API and its runtime dependencies are emitted as one Node.js bundle, so the
final image does not run a second dependency installation or ship
`node_modules`.

On the first deploy, pnpm currently resolves about 875 build packages. Future
deploys reuse the BuildKit cache unless dependency manifests or the lockfile
change. If a slow server still has a deployment command timeout below 30
minutes, raise it to 1800 seconds for the first build; normal cached redeploys
should complete well below that limit.

## Required Variables

```env
KANEO_CLIENT_URL=https://your-domain.com
```

Keep these defaults unless you have a reason to change them:

```env
SERVICE_HEX_64_AUTH=<auto-generated by Coolify>
SERVICE_PASSWORD_64_POSTGRES=<auto-generated by Coolify>
POSTGRES_DB=kaneo
POSTGRES_USER=kaneo
POSTGRES_HOST=postgres
POSTGRES_PORT=5432
FILE_STORAGE_DRIVER=local
LOCAL_UPLOAD_DIR=/app/data/uploads
FILES_MAX_UPLOAD_MB=25
```

`SERVICE_HEX_64_AUTH` and `SERVICE_PASSWORD_64_POSTGRES` are Coolify magic variables. Coolify generates them on the first deploy and keeps the same values on future redeploys.

`AUTH_SECRET` must remain stable and contain at least 32 characters. The
container intentionally refuses to start when Coolify does not provide
`SERVICE_HEX_64_AUTH`, preventing session invalidation and insecure local
upload signatures after a redeploy.

`TRUSTED_PROXY_CIDRS` defaults to the private Docker network ranges in
`compose.yml`. This lets Better Auth resolve the original client through
Coolify/Traefik and apply login rate limits per IP. Narrow the list to the
actual Coolify proxy network when its CIDR is known.

`KANEO_API_URL` is optional in the bundled container. If it is empty, the entrypoint derives it as:

```txt
KANEO_CLIENT_URL/api
```

## Persistent Volumes

The compose file creates two named volumes:

```txt
postgres_data
nortys_uploads
```

`nortys_uploads` is mounted at:

```txt
/app/data/uploads
```

Do not remove this volume unless you intentionally want to delete uploaded files.

## One-Time Clean Baseline Reset

The current database history starts at `0000_nortys_baseline` and expects an
empty PostgreSQL database. It intentionally does not upgrade databases created
by earlier Kaneo or Nortys migrations.

Before the first deployment of this baseline:

1. Back up anything you need from PostgreSQL.
2. Stop the application in Coolify.
3. Delete only the persistent volume mounted at `/var/lib/postgresql/data`
   (`postgres_data`).
4. Keep the `nortys_uploads` volume.
5. Redeploy the application. Nortys will create the complete schema
   automatically.

This reset is required only once. Future schema changes will be applied as
normal incremental migrations starting at `0001`.

## Health Check

Coolify can use:

```txt
/api/health
```

on port:

```txt
5173
```

## Local Smoke Test

```bash
cp .env.sample .env
openssl rand -hex 32
```

Put the generated value in `SERVICE_HEX_64_AUTH`, set a local `SERVICE_PASSWORD_64_POSTGRES`, then run:

```bash
docker compose up -d --build
```

Then open:

```txt
http://localhost:5173
```
